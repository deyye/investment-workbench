# 批文研析 · 文件结构化智能体

把政府投资项目的批复 PDF（项目建议书/立项、可行性研究报告、初步设计）自动读成一张表：**14 项固定字段 + 建设数字指标**，每一项都能点回原文那一行；再按项目把不同阶段的批文摆在一起对照，看哪些变了、哪些只是说法不同、哪些是原文根本没写。

> **一句话定位**：它不是"帮你读文件"，而是"帮你核对文件"。系统负责把事实抽出来并附上出处，**判断留给人**。

---

## 一、它能做什么

| 能力 | 说明 |
|---|---|
| 字段抽取 | 14 项固定字段，每项带页码、坐标区间、原文引用 |
| 指标抽取 | 从建设内容里拆出"总建筑面积约 4702 平方米"这类数字，保留指标名、单位、约数、上下界 |
| 单位归一化 | 平方米/公顷/m²/hm²、米/km、立方米/万立方米 等折算成统一口径，原始写法照留 |
| 阶段识别 | 自动判定这份批文属于建议书 / 可研 / 初设，可人工改正 |
| 跨阶段对照 | 输出「一致 / 内容变化 / 表述差异 / 未载明 / 待核对」五种状态并着色 |
| 点回原文 | 点击任意结果，跳到对应页并高亮那一段 |
| 空值两分 | **原文未载明**（灰，已全文检索核实）与**未提取到**（红，原文有线索），两者不混为一谈 |
| 人工修订 | 改值必须绑定证据；改了什么、为什么改、什么时候改全部留痕；版本冲突校验 |
| 核对进度 | 每个项目显示还剩多少项待确认，待办清单可逐条点击直达 |
| 自检循环 | 自检发现异常时自动补救（放宽章节判据、换识别形态、定点回读），修不好就**显式上报**，不静默返回空 |
| 删除 / 回收站 | 单份、整个项目、全部三种粒度；先移入回收站可恢复，彻底删除是独立动作 |
| 导出 | Excel（项目对照、单文档结构化含来源与缺失原因、证据索引、待复核事项、修订记录）+ JSON 全量 |

每批最多 10 份 PDF，单份 ≤20 MB、批次合计 ≤23 MB、单份 ≤100 页。

## 二、快速开始

要求 **Python 3.10+**（Docker 与 CI 用 3.12）。除 Python 外只有 4 个依赖：PyMuPDF、Pillow、numpy、openpyxl。

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.lock
.venv/bin/python -m app.server
```

打开 <http://127.0.0.1:8765>，把 PDF 拖进去即可。**不配模型密钥也能用**——本地规则流程完整可跑。

Windows PowerShell 把前两行换成 `.\.venv\Scripts\python.exe -m pip install -r requirements.lock`，启动同样是 `.\.venv\Scripts\python.exe -m app.server`。

**想先看效果（推荐）**：一条命令造出 7 份明确标注为虚构的演示批文并起服务，可体验进度总览、阶段覆盖、连续核对、冲突修订、差异筛选。

```bash
python scripts/demo.py --review-demo --data /tmp/approval-demo --serve
```

用自己的文件走真实解析流程：`python scripts/demo.py --samples /path/to/pdfs --serve`。

常用参数：`--port 8770`、`--host 0.0.0.0`；数据目录用环境变量 `DATA_DIR` 指定。

## 四、使用流程

1. **上传** —— 拖入 PDF，按项目自动分组（同项目的不同阶段归到一起）。
2. **核对字段** —— 左侧选项目，逐项看抽取结果。带颜色的值是系统给出的推断，点一下能看到它引用的原文。
3. **看阶段覆盖** —— 项目卡片上的阶段胶囊标出每个阶段有几份、哪个还没传。
4. **处理待办** —— 按核对进度逐条过一遍：确认、改正、或标记为"原文未载明"。改正必须挂上证据。
5. **跨阶段对照** —— 切到对照视图，看同一指标在三份批文里是否一致。系统会区分"合理演进"与"真矛盾"，前者不报红。
6. **导出** —— Excel 或 JSON，含来源与缺失原因。
7. **清理** —— 不再需要的批文移入回收站；确认无误后再彻底删除。

## 五、模型配置（可选）

不配也能用。配了之后可以开启"使用大模型辅助抽取"，用于处理规则覆盖不到的表述。

三条路径任选，**优先级：界面保存 > `.env` > 环境变量**：

1. **界面配置（推荐）** —— 左侧「模型设置」填服务地址、密钥、模型名，保存后立即生效，不用重启。任何 OpenAI 兼容服务都可以（DeepSeek、通义千问、智谱、月之暗面、硅基流动……）。存在 `data/model_config.json`。
2. **后端 `.env`** —— 复制 `.env.example` 为 `.env`，填 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL`，重启生效。
3. **环境变量** —— 同键名，适合容器部署。

几条硬约束：

- **密钥只进不出** —— 界面从不回显明文，只显示是否已配置及末四位。
- **模型不能编造** —— 模型的返回值必须是被引用行的**原文子串**，对不上就丢弃。这是防幻觉的底线。
- **只在勾选后才发送** —— 不勾"使用大模型辅助抽取"，批文不会离开本机。
- 用 `python scripts/check_model.py` 或界面上的"测试文字模型"检查真实连接（只发固定测试内容）；视觉模型加 `--vision`。

## 六、设计思路

**1. 证据优先。** 每一个值都必须能回答"它从哪来"。字段、指标、人工修订三者共用同一套证据机制（页码 + 坐标 + 原文引用）。抽不出证据的值宁可不要。

**2. 规则打主力，模型只兜底。** 政务核验要留痕、要可复现、要能解释——这些恰恰是确定性流水线的强项，而不是它的欠发达形态。所以主干是纯规则，大模型是可选的增强，且只能在异常处介入。

**3. "没抽到"和"确实没有"必须区分。** 这两者在传统输出里长得一模一样，而后果完全相反：前者是系统缺陷，后者是文件事实。系统对两者给不同的颜色、不同的措辞、不同的处理路径。

**4. 比对的目标不是"找不同"。** 匡算 → 估算 → 概算，投资额本来就该变、建设内容本来就该细化。所以先判定"这算不算真正的变化"，再决定要不要提醒人。

**5. 删除必须是可恢复的。** 人工核对成果（改过的值、绑定的证据、修订历史）只存在 `<id>.json` 一个文件里，删掉就没有第二处可查。所以删除一律是"移入回收站"，彻底删除是回收站里的独立动作。

## 七、难点

这一节是实话，不是宣传。

**① 分母不可信 —— 最容易把"合格"算成"不合格"。** 实测 47 份公开批文中，"建设周期"字段只有 1 份能抽到，覆盖率 2%，看着像重大缺陷；但逐份核对原文后，**46 份本身就没写这一项**。同一套系统，分母取"14 字段全覆盖"是 2%，取"批文实际载明项"就接近满分。**验收分数取决于口径定义，不取决于技术。**

**② 比对没有天然基准。** 严格说，跨阶段比对本该是"人拿着两份文件比"。系统能做的是把候选差异摆出来并分级，无法替代人对"这个变化合不合理"的判断。更麻烦的是**假警报比漏报更致命**——红标多了，人就开始忽略红标，机制自我失效。

**③ 图片层。** 相当一部分政务公文的红头、标题、印章在图片层，不进文本层。只能靠 OCR，而 OCR 会从水印上"读"出乱码——所以必须先用墨迹占比判断这一页是不是真空白页，**再决定要不要采用 OCR 结果**（顺序反了就会把空白页的乱码收进正文）。

**④ 指标起名是语言任务，不是匹配任务。** "总建筑面积约 4702 平方米"里，"4702"是数值、"平方米"是单位，都好办；难的是给它起一个规范的名字"总建筑面积"。规则能定位数值和位置，但起名会出错——曾经把动词短语当成了指标名，产出语义错误的条目。**"规则抽数值+位置、模型只负责起名"是清晰的分工边界。**

**⑤ 百万级 × 可复现。** 平台上有百万级文件，成本不允许逐份调模型；而核验场景又要求每一步可复现、可审计。实测单份约 1.5 秒（不含模型），架构上只能"规则打主力、模型在异常处兜底"。**另外，错误是静默的——输出 0 条指标和输出 45 条，界面上一样自信。** 这正是自检循环存在的理由：它把"系统不知道自己错了"变成可审计的显式记录。

## 八、后续优化方向

按性价比排序：

1. **指标名自动规范化** —— 规则给出数值与位置，模型只补名字，两者拼装。这是唯一能解"数字在正文叙述里、不在章节标题下"这类文档的路。
2. **同名指标作用域分层** —— 现在"同名不同值"一律标冲突，偏保守。实测 25 组同名多值里只有 1 组是真矛盾，其余是"分项明细"或"总计=分项之和"。需要按作用域/层级区分。
3. **大批量吞吐** —— 面向百万级文件的批处理、断点续跑与跨文档记忆。
4. **口径归一化** —— 发文字号全角/半角、阶段归类的判定依据（标题不等于阶段，存在标题写作"立项申请批复"但实为项目建议书批复的情况）。
5. **更强的规划器** —— `agent_loop.py` 已把循环与决策解耦成同一接口，默认走确定性规则规划器；接上模型后可在更复杂的异常上自动决策。
6. **回收站治理** —— 容量上限与清理策略（当前无上限），以及删除与正在运行的抽取任务并发的时序。

## 九、测试 · 评测 · 部署

**测试**（201 项 Python 单测 + 1 项前端交互契约，CI 全跑）：

```bash
python -m unittest discover -s tests -v
node tests/test_ui.cjs
```

历史材料回归测试需要本机 `SAMPLE_DIR`，未设置时自动跳过——公开 CI 不依赖私有材料。

**评测**（公开部分只有虚构演示）：

```bash
python scripts/demo.py --data /tmp/approval-demo
python scripts/evaluate.py --samples /tmp/approval-demo/demo-source
```

6 份虚构批文上的成绩：固定字段 84/84、证据页召回 84/84、建设指标精确率与召回率均为 1.00，单份约 0.2 秒。**这是自造标注集的成绩，不代表未知文档的泛化准确率。**

私有材料请在本机评测，不要提交到公开仓库：

```bash
python scripts/evaluate.py --samples /path/to/private/pdfs --gold /path/to/private/gold.json --out /path/to/private/results
```

**部署**：

```bash
cp .env.example .env
docker compose up -d --build --wait
```

镜像含中文 OCR、以非 root 运行、带健康检查与数据持久化。模型配置、密钥挂载、服务器访问、备份与故障处理见 [外部模型与 Docker 部署](docs/MODEL_DOCKER.md)。

**技术栈**：Python 标准库 HTTP 服务 + PyMuPDF + NumPy/Pillow + openpyxl；前端原生 JavaScript，**无需 Node 构建**（`npm run dev` 只是可选的启动入口，运行时仍是 Python）。
