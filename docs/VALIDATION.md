## 追加轮次：列表页细节打磨（2026-09-16 晚）

`python -m pytest tests -q`：**421 passed, 10 skipped, 22 subtests passed**，约 77 秒。

背景是拿真实库（1070 条政策、37 条运行记录）用起来之后暴露的三个短板：
政策库一页 20 条只能逐页翻、固定按 id 倒序（"看最近发布的政策"做不到）、
`?page=99` 返回一页空白；处理进度页固定只取最近 50 条且没有翻页。

改动与实测：

- **政策库排序**：表头 7 列均可点，带方向箭头与 `aria-sort`；空日期恒沉底（升/降序都沉底）；
  同日期的记录以 id 兜底保持稳定次序（否则翻页会重复或漏条目）。未知列名/方向安静回落默认，不 500。
- **分页**：每页 20/50/100（白名单，`per=0` 与 `per=100000` 都被挡回默认）；
  显示"共 N 条 · 第 x/y 页"；支持跳页与上一页/下一页。总页数由**总数**算出，
  不再用"本页是否取满"倒推（旧写法在总数恰为整页倍数时会多给一个指向空页的"下一页"）。
- **页码越界夹住并说明**：`?page=999` 跳到最后一页并提示，而不是给一页空白。
- **参数不丢**：翻页/跳页/换排序都保留筛选条件；改筛选条件则回到第 1 页。
- **导出当前筛选（CSV）**：带 UTF-8 BOM（Excel 打开中文不乱码），与列表页共用同一套筛选与排序口径；
  只在有结果时显示按钮。实测导出浙江 165 条：`地区` 唯一值仅"浙江"，按日期倒序，用 `utf-8-sig` 读回 165 行、11 列。
- **修掉一处"看起来生效、其实没显示"的缺陷**：政策库「状态 / 待办」列原本引用
  `todo_names` / `todo_owners` 两个不存在的变量，Jinja 的 Undefined 让 `in` 判断静默为假，
  整列改走 else 分支把原始英文 `review_status` 印成绿色"正常"标签——20 行全是 `pending`，
  真正的待办类型与责任方一个字都没显示。已改为读 `TODO_META`，并把复核状态中文名收敛成一处。
- **顺带**：`table.list.wide` 这个类名此前只在模板里写了、CSS 里没有定义，已补最小宽度；
  政策详情页"返回政策资料库"在同源来路下走 `history.back()`，不再丢掉刚才的筛选与页码。

新增 `tests/policy/test_list_sort_paging.py`（14 项），按数据层/参数层/页面层/回归层分开断言。
另在装配后的应用上实测：挂载前缀 `/policy/policies` 下的表单 action、导出链接与排序链接均正确带前缀。
